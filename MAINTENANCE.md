# Maintenance

Maintenance is best effort, with no fixed response time or release schedule.

Pull requests run SDK-endpoint analysis and package tests. Weekly checks cover stable compatibility and dependency updates. Platform changes and release candidates run the full platform matrix. Changes are reviewed manually; merging and publication are not automatic.

Prioritize crashes, incorrect dates/times, resource lifetime and SDK compatibility. Stable releases follow SemVer; breaking public contracts and SDK-floor changes require migration guidance. [QA](doc/QA.md) defines release checks.
